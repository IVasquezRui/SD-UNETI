# CI/CD 2026 — workflows, QA y pentesting

> Estrategia de integración y entrega continua del portal SD-UNETI, diseñada para el plan gratuito de GitHub Actions en un repositorio privado.

## 1. Presupuesto

GitHub Free para repositorios privados incluye **2.000 minutos/mes** en runners Linux. Todos los workflows usan `ubuntu-latest` (multiplicador 1x), `timeout-minutes`, `concurrency` y filtros `paths`.

| Escenario | Estimación mensual |
|---|---|
| 20 pushes con cambios de frontend + despliegue + formulario | ~420 min |
| 10 pushes con cambios de WordPress | ~75 min |
| 4 ejecuciones de seed | ~60 min |
| Pentests mensuales (3 × ~7 min) | ~21 min |
| QA externo manual | ~5 min |
| **Total razonable** | **< 600 min/mes** |

Medidas de ahorro:

- `03-frontend.yml` no construye Next.js: el build se valida en `01` y `04` con WordPress arriba.
- `seed.yml` ya no se ejecuta por cambios de `frontend/**` ni construye el frontend.
- Los pentests son manuales y mensuales, no por push.
- `05-qa.yml` no levanta contenedores.
- Artefactos con retención de 5–7 días.

## 2. Workflows

| Archivo | Disparador | Propósito |
|---|---|---|
| `seed.yml` | Push/PR en `seed/**`, `scripts/seed/**`, `scripts/wordpress/**`, compose; manual | Fixtures, bootstrap, idempotencia y `verify`. |
| `01-despliegue.yml` | Push a `main` con infraestructura/frontend; manual | `.env`, `docker compose config`, db+WordPress+frontend de producción, seed, QA y pruebas de WordPress. |
| `02-wordpress.yml` | Push/PR en `scripts/wordpress/**`, `seed/**`, compose; manual | Lint PHP, CPT, REST, WPGraphQL y endurecimiento. |
| `03-frontend.yml` | Push/PR en `frontend/**`; manual | `npm ci`, TypeScript y ESLint con Node 26. |
| `04-formulario.yml` | Push/PR en API, formulario, mu-plugin o compose; manual | Envío real y persistencia del folio en MariaDB. |
| `05-qa.yml` | Manual | QA de una URL pública: rutas, contenido, enlaces e imágenes. |
| `06-pentest-nextjs.yml` | Manual + mensual (día 1) | Cabeceras, archivos expuestos, API y Nuclei. |
| `07-pentest-wordpress.yml` | Manual + mensual (día 8) | Enumeración, XML-RPC, archivos sensibles, WPScan y Nuclei. |
| `08-pentest-mariadb.yml` | Manual + mensual (día 15) | Puerto, privilegios, acceso remoto y `local_infile`. |

## 3. Acción compuesta

`.github/actions/preparar-entorno/action.yml` crea un `.env` efímero con:

- Contraseñas de prueba.
- `UNETI_FORM_TOKEN=ci-form-token`.
- Nombres de contenedores y red aislados (`uneti-ci-*`).
- Directorios de datos en `/tmp/uneti-ci/`.

Nunca se usan secretos productivos en CI.

## 4. QA local

`scripts/ci/qa-frontend.sh` verifica:

- `/`, `/nosotros`, `/carreras`, `/cursos`, `/noticias`, `/admisiones` y `/contacto` responden 200.
- El hero del inicio usa `contacto-estudiantes.webp` y el de `/contacto` usa `hero-comunidad.webp`.
- La cabecera contiene “Ir al Campus Virtual”.
- `/nosotros` contiene flashcards, storytelling y parallax.
- `/admisiones` contiene el formulario animado.
- No aparecen `SIS-UNETI`, `SISU` ni “beca” en las páginas públicas.
- Los enlaces internos y las imágenes locales responden.

## 5. Pentesting

Cada script imprime `[POSITIVO]` o `[NEGATIVO]`, escribe un Markdown en `reportes/` y termina con:

```text
RESULTADO GENERAL: POSITIVO (0 brechas)
```

o

```text
RESULTADO GENERAL: NEGATIVO (N brechas)
```

Si hay una brecha, el job falla y el reporte queda en el artefacto y en el resumen del job.

### Next.js

- Cabeceras CSP, `nosniff`, `Referrer-Policy`, `X-Frame-Options` y `Permissions-Policy`.
- Ausencia de `X-Powered-By`.
- `/.env`, `/.git/config`, `package.json`, `next.config.ts` y source maps no accesibles.
- `__nextjs_original-stack-frames` no accesible.
- `TRACE` bloqueado.
- `/api/admisiones`: GET 405, JSON inválido 400/415, origen ajeno 403.
- Nuclei con severidad alta/crítica.

### WordPress

- `/wp-json/wp/v2/users` no enumera usuarios.
- `?author=1` no revela el slug.
- XML-RPC bloqueado; `X-Pingback` ausente.
- `readme.html`, `license.txt`, `wp-config.php.bak`, `.env` y `debug.log` bloqueados.
- Uploads sin listado.
- Endpoint de solicitudes: GET 405 y POST sin token bloqueado.
- WPScan: si existe el secret `WPSCAN_API_TOKEN`, enumera plugins y temas vulnerables; sin token ejecuta enumeración básica de usuarios, backups de configuración y exports de base de datos.
- Nuclei con severidad alta/crítica.

### MariaDB

- Puerto 3306 no publicado en el host.
- `root` solo para localhost.
- Sin usuarios anónimos.
- `wp_user` sin privilegios globales, `FILE`, `SUPER` ni `GRANT OPTION`.
- Solo ve `wordpress_db` e `information_schema`.
- `local_infile=OFF`.
- `LOAD_FILE` no puede leer `/etc/passwd`.
- `root` no puede conectarse desde otro contenedor.

## 6. Ejecución manual

```bash
# QA contra un despliegue
gh workflow run 05-qa.yml -f base_url=https://www.uneti.edu.ve

# Pentests
gh workflow run 06-pentest-nextjs.yml
gh workflow run 07-pentest-wordpress.yml
gh workflow run 08-pentest-mariadb.yml
```

También se pueden lanzar desde la pestaña **Actions** de GitHub.

## 7. Limitaciones

- El repositorio es privado: el agente no puede leer los resultados de Actions. El equipo debe reportar los fallos para corregirlos.
- `01-despliegue.yml` valida el stack en el runner; no sustituye un despliegue productivo con TLS, reverse proxy y backups.
- GitHub desactiva los workflows programados tras 60 días sin actividad; se pueden relanzar manualmente.
- Los pentests son comprobaciones automatizadas, no una auditoría profesional.
- La CSP usa `'unsafe-inline'` para compatibilidad con el template; una fase futura debe migrar a nonces.

## 8. Endurecimiento aplicado

- `frontend/next.config.ts`: `poweredByHeader: false` y cabeceras de seguridad.
- `scripts/wordpress/php/seguridad.ini`: `expose_php=Off`, errores ocultos, cookies `HttpOnly`/`SameSite`.
- `scripts/wordpress/apache/seguridad.conf`: sin listados, bloqueo de archivos sensibles y PHP en uploads.
- `scripts/wordpress/mu-plugins/uneti-seguridad.php`: XML-RPC, pingback, generator, application passwords y usuarios REST.
- `docker-compose.yml`: MariaDB sin puerto publicado, `local-infile=0` y `skip-name-resolve`.
